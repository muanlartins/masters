Interpretação dos Resultados

🛰 GPS_Tracker — binário destaque (F1 = 0.876)

Latitude e longitude são discriminadores naturalmente fortes: coordenadas de tracking malicioso formam clusters geoespaciais distintos dos padrões normais de GPS. Com apenas bits_total = 8 (bpi = 4), o BTHOWeN consegue separar bem as classes. A melhor config usa filter_entries = 16 e ocupa apenas 8 bytes de memória teórica — demonstrando a eficiência extrema do modelo para features de alta qualidade.

🌦 Weather — boa generalização (binário F1 = 0.781, AUC = 0.879)

Temperatura, pressão e umidade formam um espaço de 3 dimensões onde anomalias de sensores se manifestam como desvios coerentes. No multiclasse, o AUC sobe a 0.899 enquanto o F1 fica em 0.522 — indicando que os scores do modelo rankeiam bem as classes mas as fronteiras de decisão são difusas entre tipos de ataque similares. O termômetro gaussiano captura bem a distribuição das leituras físicas.

❄ Fridge · 🔌 Modbus · 🌡 Thermostat — próximo de 0.5

Todos os três ficam com F1 ≈ 0.50–0.53 no binário, essencialmente aleatório. No Fridge, a única feature contínua é fridge_temperature; ataques como backdoor e ransomware não alteram fisicamente a temperatura. No Modbus, os registros Modbus (fc1–fc4) são contadores cumulativos cujos valores se sobrepõem entre tráfego legítimo e malicioso — o modelo não tem sinal relevante para aprender. No Thermostat, os dois features disponíveis (current_temperature + thermostat_status) também não discriminam ataques de rede.

🔢 GPS_Tracker multiclasse — F1 baixo, AUC alto (0.357 / 0.770)

Com apenas 2 features e múltiplos tipos de ataque, as fronteiras de decisão no espaço lat/lon se tornam ambíguas. O AUC = 0.77 mostra que o modelo ranqueia as classes melhor que o acaso, mas não consegue atribuir a classe correta com alta confiança quando os clusters se sobrepõem. Aumentar bits_per_input para 32 (melhor config) ajuda a refinar as fronteiras via maior resolução do termômetro.

🚪 Garage_Door · 💡 Motion_Light — 100% skipped

Ambos os dispositivos têm exatamente bits_total = 2: uma feature numérica booleana (0/1, sem termômetro) mais uma feature categórica binária. Todos os valores de filter_inputs ∈ {4, 6, 8} excedem esse limite, tornando as 216 configurações de ambos os tasks inviáveis para essas bases. Para que fossem executadas, seria necessário adicionar filter_inputs = 2 ao grid ou agregar features externas.

📐 Pareto: modelos mínimos dominam

Na análise Pareto (memória × F1), a melhor config do GPS_Tracker ocupa apenas 8 bytes com F1 = 0.876. Para Weather binário, o ótimo usa 2 KB com F1 = 0.781. Isso indica que, para features de alta qualidade, filtros pequenos (fe = 16–256) são suficientes e evitam overfitting de contagem. Configurações com fe = 1024 raramente superam o desempenho de filtros menores neste dataset, mas dominam em memória.
